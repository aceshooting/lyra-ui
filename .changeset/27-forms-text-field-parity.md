`lr-phone-input` now matches `lr-input`/`lr-textarea` native passthrough: `autocorrect` is a boolean (the string `autoCorrect` property is removed; use `autocorrect`, `.autocorrect=${false}` or `autocorrect="off"`), `inputMode`/`enterKeyHint` are the camel-case properties with the lowercase names kept as aliases, and the host `name` is forwarded to the internal field (also on `lr-textarea`). `lr-input`, `lr-textarea` and `lr-phone-input` share one per-appearance fill/border fragment, and `lr-time-range` and `lr-date-picker` share one preset-button paint (hover now fills and recolors the border on both; new `--lr-time-range-preset-hover-bg` and `--lr-date-picker-preset-{hover,pressed,selected}-border-color` tokens, old names kept as fallbacks). A focusout while the host is already `:disabled` no longer marks a form-associated control as interacted. `lr-date-input` follows the same shape: the string `autoCorrect` property is removed in favour of the boolean `autocorrect`, the lowercase `inputmode`/`enterkeyhint` aliases exist, and host `name` is forwarded to its native input (as it is on `lr-otp-input`). `lr-date-input` and `lr-time-input` now take their per-appearance fill and border from the same shared fragment. `lr-time-range` relays host `focus`/`blur` once on entering and leaving the control, no longer when focus moves between its two handles. `lr-model-select`, `lr-voice-picker` and `lr-menu` share the popup controller's outside-press binding; `lr-model-select` and `lr-voice-picker` now share one form-association implementation. `lr-model-select` and `lr-voice-picker` likewise replace the string `autoCorrect` property with the boolean `autocorrect` (use `autocorrect`, `.autocorrect=${false}` or `autocorrect="off"`).
