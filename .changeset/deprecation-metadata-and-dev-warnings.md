Deprecation metadata now covers more than single members. A `slot-content` record deprecates a kind of content inside a slot that stays supported, and package entry points and exported types have their own records, listed under "Deprecated package exports" in `llms/index.md`. Some deprecations now also log one development-mode `console.warn` per page for each element name and deprecated API, naming the replacement, when a component can observe the usage cheaply and exactly (setting a deprecated property or attribute, connecting a deprecated tag, or vetoing through a deprecated alias event). Not every deprecated API warns: deprecations such as `lr-icon`'s `auto-width`, `lr-stat`'s default-slot icon, `lr-menu`'s non-item default-slot content, and the `lr-before-*`/`lr-open` alias events do not, and deprecated CSS parts, custom properties, and custom states never do, so the deprecation records remain the complete list to audit against. The warning appears only when Lit runs its development build, never in production, and the deprecated form keeps working. Test suites that fail on console output can pre-seed the warning's key, `lyra-deprecated:<tag>:<kind>:<name>`, in Lit's `globalThis.litIssuedWarnings`; `llms/shared.md` documents the format.
