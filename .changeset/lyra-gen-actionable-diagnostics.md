Validation errors are now actionable for models and common content mistakes can enter the repair loop. Every diagnostic a model can fix carries a concise `hint`: allowed enum values, the expected type and bounds of a value, the missing required property and its shape, the nearest declared name for an unknown component, property, slot, action, query or state path, and the owning node for a duplicate identity or an overlapping binding; hints never repeat generated values. Content-shape failures that `recovery: 'isolate'` can contain (unknown properties and component types, reads of unowned state, wrong types, out-of-range values, missing required properties) are now in `REPAIRABLE_DIAGNOSTIC_CODES`, and the new `isRepairableDiagnostic()` keeps schema failures outside a node's own properties, such as action payloads, terminal; identity, binding ownership, content policy, catalog version, revision and resource-limit failures stay non-repairable, and every repaired candidate is still validated as a whole. The new `formatRepairMessage(diagnostics, { maxCharacters, view })` renders diagnostics as a compact, deterministic, size-bounded repair instruction grouped by node.
