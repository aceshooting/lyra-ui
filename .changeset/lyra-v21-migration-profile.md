`lyra-ui-migrate` gains `--origin=lyra-v21`, a Lyra-to-Lyra profile for this release's deprecated Lyra-only names. It rewrites a name only where the rewrite cannot change which components a site reaches: `code-block-chrome`/`codeBlockChrome` becomes `code-block-header`/`codeBlockHeader` on `lr-markdown`, `lr-markdown-core`, `lr-message-parts`, `lr-streaming-text` and `lr-streaming-text-core`; `lr-mutation-observer`'s `character-data`/`characterData` becomes `char-data`/`charData`; and `lr-before-media-download` listeners move to `lr-media-download-request`, except where the same receiver already listens to `lr-media-download-request` with the same handler, which would collapse two registrations into one. Every other deprecated use is reported with its file, line, column, warning code and replacement instead of being rewritten: the `lr-geojson-view` tag, `lr-icon`'s `fixed-width`/`fixedWidth` and `--lr-icon-fixed-width`, `lr-mutation-observer`'s `attributes`/`observeAttributes`, `lr-sparkline`'s `area` part and `--lr-sparkline-stroke-width`, `lr-split-panel`'s `split-panel` part, an unnamed `lr-stat` icon, and, from 22.0.0, `lr-menu` default-slot content other than items, labels and separators. `--diff` previews any migration as a `git apply` patch without writing, `--lyra-version=x.y.z` applies only the entries available in that release (by default the `@aceshooting/lyra-ui` installed under the working directory), and a `lyra-migrate-reviewed: CODE:name` comment acknowledges a reviewed report so `--check` can gate the migration in CI. Every deprecated name keeps working until 23.0.0, so running the profile within 21.x is optional; `llms/migration.md` lists each entry. Templates rendered on the server must be re-rendered after migrating, because Lit hydration compares template strings.
