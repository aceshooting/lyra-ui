`lr-tool-call-block` and `lr-tool-call-chip` gain a `displayName` property (`display-name` attribute) for the application's own, already-translated tool label. It replaces only the tool name: the block's header keeps its localized status verb around it (`Used Lecture d’un fichier`), the chip shows it in its `name` part and accessible name, and `name` still selects the result renderer and is still reported in `lr-render-error` and `lr-tool-call-chip-select`. The shared tool-call status vocabulary (`ToolCallStatus`, `ToolResultStatus`) gains `incomplete` for a call that ended without a result, such as an interrupted stream or a cancelled run. It has its own static glyph, the neutral tone, and localized default text in every shipped catalog: `Incomplete` (`statusIncomplete`) and, in the block header, `Did not finish using {name}` (`toolCallBlockHeaderIncomplete`). The chip, block, result dialog and tool timeline accept it. The dialog adds `--lr-tool-result-dialog-incomplete-color` and `--lr-tool-result-dialog-incomplete-bg`, and the timeline adds `--lr-tool-timeline-incomplete-marker-color`, so restyling `pending` no longer restyles `incomplete`. `ToolInvocation` (from `@aceshooting/lyra-ui/ai`) gains an optional `displayName`, which `lr-message-parts` forwards to the chip or block in either tool display and `lr-tool-timeline` shows on each entry's chip and details disclosure. The stream runtime now accepts `status: 'incomplete'` and a string `displayName` on `tool-upsert` events, `tool-call` parts and message snapshots, where `incomplete` previously failed the stream as an invalid event. In `lr-message-parts` block display, an invocation marked `incomplete` keeps that status whatever result part is paired with it. Existing statuses and defaults are unchanged. TypeScript code that switches exhaustively over `ToolCallStatus` or `ToolResultStatus` needs an `incomplete` case.
