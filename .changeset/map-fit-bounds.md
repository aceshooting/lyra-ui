`lr-map` gains `fitBounds(bounds, { padding?, maxZoom?, animate? })`, which frames a `[[west, south], [east, north]]` box (for example every current marker, or a selected region) without fighting the element's own `center`/`zoom` updates. The settled camera is written into `center` and `zoom` and reported through the new `lr-map-view-change` event (`detail: { center, zoom, source }`, `source` being `'user'` or `'fit'`), so declarative state stays in sync and the next update never resets the fitted camera. The method can be called before the map exists: the latest request is queued and applied on construction, unless `center` or `zoom` has been given a different value since the call (re-assigning an equal value keeps it). It never animates under `prefers-reduced-motion`, accepts both of MapLibre's antimeridian forms (`west > east`, or `east` unwrapped past 180), and returns `false` for an unusable box.

`lr-map-view-change` also fires after user gestures (drag, wheel, touch, keyboard, Shift+drag box zoom, navigation buttons), so `center` and `zoom` now track the camera the user settles on; assigning them still moves the map without emitting anything. Three consequences worth knowing: assigning a value the map already shows no longer re-jumps the camera, so echoing a reported camera back never interrupts an animation or gesture; an assignment that does interrupt one applies both `center` and `zoom`, instead of leaving the unassigned one wherever the movement stopped; and a map rebuilt after a disconnect/reconnect now opens at the last settled camera rather than the originally declared one. New types: `LyraMapFitBoundsOptions`, `LyraMapPadding`, `LyraMapViewChangeDetail`, `LyraMapViewChangeSource`.
