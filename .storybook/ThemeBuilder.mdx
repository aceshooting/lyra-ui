# Theme builder

[Open the theme builder](?path=/story/theming-theme-builder--editor) to preview real controls while choosing a look, surface, density, mode and accent. Advanced sections edit motion, script-aware font pairing, shape, elevation and chart colors. The editor stays in its own readable scope while the two specimens show your selection in both modes.

The builder runs only in the documentation site. It adds no package dependency, custom element or application storage record. It downloads no fonts or chart engines. Selecting a script uses local fonts with system fallbacks; inspect your actual content with the fonts installed on your users' platforms.

## Edit and reset

Selecting another look preserves your other axes and options. A preset replaces its own token group. Manual field edits take precedence over presets. **Changed tokens** shows the resulting override map.

**Reset this group** removes that group's edits. **Use look value** removes the selected token from every override group. **Reset all** restores the initial Lyra, solid, comfortable, light preview without an accent, and returns preferences to system; **Undo reset** restores the preceding draft. None of these actions changes the Storybook toolbar or an application's saved preferences.

Fast and normal motion inputs control discrete transitions. Slow controls ambient cycles; icon controls icon cycles. Explicit and operating-system reduced motion remain authoritative. The replay action is finite and user initiated.

Shape changes preserve explicit pill/circle geometry and local component overrides. Elevation changes shadows and surface roles, never stacking order. A component whose default shadow is none stays flat unless it opts into the shared scale; the preview card deliberately opts in.

If a preview language fails to load, the current language and draft stay in place. **Reload and restore draft** captures your choices and any later edits when you click it, saves a one-use copy in this tab's session storage, and reloads the editor. It restores the draft, reset undo, editor fields and open groups, then tries the requested language once. An explicitly chosen direction stays unchanged. A repeated network failure shows the action again; it never reloads automatically.

The recovery copy expires after five minutes and is consumed before restoration. If storage is unavailable, the editor stays open so you can use **Export** before reloading. Invalid or incompatible recovery data applies no saved choices. When a bounded copy can be safely consumed, **Download recovery data** keeps it available for inspection until you leave the page; this private recovery envelope is not an importable theme format. Ordinary editing remains in memory.

## Import existing formats

Paste JSON or select a file up to 256 KiB. Validation completes before the preview changes. Invalid data remains available for correction, with a field-specific error. Imported strings are data, never JavaScript or an arbitrary stylesheet. URL-bearing CSS, executable input and unsupported variable references are rejected.

| Format | Effect |
| --- | --- |
| Look `{ id, tokens }` | Replaces only the look; token pairs retain light/dark branches |
| `LyraThemeTokens` map | Replaces imported token overrides |
| Version-2 saved style record | Replaces axes, runtime look tokens and overrides |
| `LyraPreferences` | Replaces requested contrast/motion preferences |

The saved style record uses `treatment` for solid/glass and `surface` for an accent reference background. The live API uses `surface` and `accentBackground` respectively. Portable exports preserve these existing formats; the private one-use reload recovery envelope is separate from them.

## Export and application setup

**Recipe** provides scoped runtime calls and explicit imports. **Look** and **CSS** compose the authored look and edited overrides under your application-owned id. **Tokens** exports only overrides. **Style record** retains the selected axes and runtime look map. Preferences use a separate file because the style storage format does not contain them.

A look stylesheet is only one part of a complete selection. Install `theme.css`, the exported stylesheet, and the optional surface/density/accent/preference sheets named in the export. Add the selected axis attributes. A custom runtime accent also needs the runtime recipe; exporting look CSS alone does not reproduce that derivation.

```js
import '@aceshooting/lyra-ui/theme.css';
import '@aceshooting/lyra-ui/preferences.css';
import { defineLyraLook, applyLyraStyleScope } from '@aceshooting/lyra-ui/theme.js';
import { applyLyraPreferences } from '@aceshooting/lyra-ui/theme/preferences.js';

const look = defineLyraLook({
  id: 'my-look',
  tokens: { '--lr-theme-border-radius-container': '0.75rem' },
});
applyLyraStyleScope(previewElement, { look, mode: 'system' });
applyLyraPreferences(previewElement, { motion: 'system', contrast: 'more' });
```

For server rendering, `lyraLookCss()` produces DOM-free look CSS. `lyraStyleAttributes()` and `lyraPreferenceAttributes()` produce requested attributes for an escaping template renderer. System mode remains unresolved until the browser. Custom accents are also derived in the browser: server-rendered look CSS and requested attributes provide the base look as an explicit initial fallback, not equivalent pre-painted custom accent colors. Install required CSS inside application-owned shadow roots that contain local style boundaries. The whole-page bootstrap/persistence APIs remain optional application choices; the builder does not call them.

## Read diagnostics accurately

Diagnostics measure rendered semantic pairs, meaningful boundaries, the current brand-button interaction state, categorical and magnitude-scale fill contrast, and simulated color-vision separation. Ratios identify the relevant text/non-text threshold. Focus results remain unmeasured until real keyboard focus reaches the specimen. Requested accents can produce corrected rendered fill/on-color pairs; the original accent input is not itself a contrast guarantee.

Unknown or dynamic backgrounds, including glass backdrops, do not receive a pass. A passing specimen does not certify every component state or arbitrary application content. Sequential and diverging fills retain visible numeric labels and boundaries; chart series retain labels and marker/dash cues. Color-vision distances are heuristics, not a substitute for those cues.

Use keyboard navigation, RTL, long labels, narrow widths and text zoom when reviewing a result. Physical backdrop blur, installed-font shaping, Safari Reduce Transparency and Windows High Contrast need evidence on the relevant platforms; browser emulation does not establish that qualification.
