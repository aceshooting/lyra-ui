# Input validation boundaries

Lyra accepts document bytes, structured application data, element attributes, provider results,
URLs and browser interaction data. Validation follows the input's use: typed records, indices,
finite coordinates and resource metadata have constrained forms; ordinary labels and document
text remain text. A renderer, formatter, worker, protocol handler or loader supplied as a function
is application code. It is not a sandboxed data source.

The controls below reject, omit, or normalize invalid values to the documented default before
their consuming operation. This inventory identifies concrete shared controls and the package
boundaries where they apply. A TypeScript declaration or the presence of a
helper import is not itself runtime validation.

## Documents, markup and subresources

Resource loaders resolve URLs against the owning browser realm and apply actual response-byte
ceilings while reading. Parser-specific admission follows that transport boundary; a byte limit
alone is not a document schema. Stale async results are discarded before publication.

| Input | Parser/sink controls and refusal | Evidence |
|---|---|---|
| HTML/SVG/includes/icons | DOMPurify is required before markup insertion. Passive profiles remove navigation, active/custom content and secondary network sinks; only specified local fragments/inline raster references survive. Missing sanitizer or malformed SVG fails visibly. Includes/icons have smaller byte limits and bounded caches. | [passive policy](../packages/lyra-ui/src/components/viewers/passive-markup.ts), [tests](../packages/lyra-ui/src/components/viewers/passive-markup.test.ts), [icon admission](../packages/lyra-ui/src/components/utility/icon/icon-resource.ts), [include admission](../packages/lyra-ui/src/components/viewers/include/include-resource.ts) |
| CSV/dataset | Quote-aware preflight and streaming parser callbacks enforce row/column/cell/diagnostic limits. Owned table inputs use dimension/materialization guards. Recoverable parser diagnostics may retain a normalized partial table and remain explicit diagnostics. | [delimited admission](../packages/lyra-ui/src/internal/delimited-data.ts), [tests](../packages/lyra-ui/src/internal/delimited-data.test.ts) |
| Spreadsheet | ZIP/XML expansion and row/cell work are checked before workbook conversion. Sheet names/counts and ranges are checked before table materialization. General image/audio/video controls deliberately use browser media decoders after validating their
URL sink. They do not inherit the DOCX editor's narrower static-image admission policy. Likewise,
archive listing, document opening, editing and executing a supplied application callback are
different operations; their constraints are described at the corresponding boundary.
