# Input validation boundaries

Lyra accepts document bytes, structured application data, element attributes, provider results,
URLs and browser interaction data. Validation follows the input's use: typed records, indices,
finite coordinates and resource metadata have constrained forms; ordinary labels and document
text remain text. A renderer, formatter, worker, protocol handler or loader supplied as a function
is application code. It is not a sandboxed data source.

The controls below reject, omit, or normalize invalid values to the documented default before
their consuming operation. This inventory identifies concrete shared controls and the package
boundaries where they apply. A TypeScript declaration or the presence of a
helper import is not itself runtime validation.

Prepared companion mutations preserve native canvas handles and the documented custom-layer
`render`, `prerender`, `onAdd` and `onRemove` callbacks. Those callbacks, registered protocols and
supplied loaders/workers are application code. Canvas allocation, content and playback remain
caller/browser-owned. Renderer-fetched style, tile, TileJSON and external image URLs use the
renderer transport and schema policies; the registered-image response/decode limits above do not
apply to those requests or to a caller's already-created canvas. Descriptor ownership checks do
not sandbox executable proxies or callbacks, and metadata admission does not replace native
raster decoding.

## 3D engine data, media and model bytes

The engine entry points accept different input kinds. Graph and points use application-created
typed columns; panorama receives already-loaded native media; model admission receives file bytes.
These operations do not share a universal document parser or image policy.

|---|---|---|
| Graph topology and layout | Node/edge counts, typed-column lengths, endpoint indices, finite coordinates, pin masks and layout options are checked before solver work. Typed-column and state setters are application APIs, not generic record deserializers. They read
application-owned properties directly; they do not apply Lyra UI's descriptor-only collection
snapshot policy. Accessors, proxies, custom state iterators and replacement task/parser/media
services remain application code. Graph, points and panorama numeric columns require ordinary
`ArrayBuffer` backing; shared buffers reject before their elements are inspected or copied.
[Shared-buffer regressions](../packages/lyra-3d/test/shared-buffer.test.mjs) cover each admitted
column family and pin updates.

Panorama's limits apply after the caller/browser has loaded the media, not before its original
network transfer or decoding. Model admission instead applies before its own format loaders and
embedded-image decoders. Neither engine supplies a source-URL transport policy for an application
that loads model bytes itself. Supported model syntax restrictions, including PLY header boundaries
and OBJ point/line separators, are listed in the [companion contract](../packages/lyra-3d/README.md).
Numeric model-token and core color parsers separate digit runs with required delimiters to avoid
ambiguous repetition while retaining their documented grammar.

ceilings while reading. Parser-specific admission follows that transport boundary; a byte limit
alone is not a document schema. Stale async results are discarded before publication.
